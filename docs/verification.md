# 구현과 검증 기록

- 실행 환경: Node.js 24, 외부 런타임 의존성 없음.
- 서버 자동 검증: 19개 통과. HTTP CRUD/기기 격리, 입력 검증, 저장 직렬화와 재시작, 외부 버스 API 실패/빈 결과, RFC8291 공식 암호화 벡터, ES256 서명, 푸시 목적지 검증, 서울 요일/자정, 중복 발송, 실패 재시도, 만료 제거와 재연결 동시성.
- 독립 코드 검토 완료. 기존 구독 요청의 실패가 새 구독을 삭제하는 문제, 설정 변경 중 이전 발송 완료가 새 설정 이력을 덮는 문제, 별칭/토글 변경으로 중복 방지가 초기화되는 문제, 임의 쿠키를 통한 요청 제한 우회에 대해 실패 재현 후 수정하고 테스트를 통과시켰다.
- Playwright: 390px / 1440px 검색 빈 결과, 경로 생성, 새로고침 유지, 수정, 삭제, 가로 넘침, JS 오류, 7블록 페이지 검사. 로컬 환경에서 Chromium 다운로드가 실패하여 GitHub Actions에서 수행한다. 초기 CI의 숨겨진 화면 선택자 오류는 실제 실패 로그를 확인하고 활성 화면에 한정하도록 수정했다. 최종 실행 결과는 PR의 Actions 검사가 기준이다.

## 구현 판단

- 지역 미지정 → 서울 제공처를 먼저 구현. 다른 지역은 별도 어댑터 필요.
- 지도/길찾기 키 미제공 → 도보 시간 직접 입력. 자동 계산으로 오인시키지 않는다.
- 버스 키 미제공 → 명시적 체험 모드, 자동 버스 알림 없음.
- 기기 쿠키로 가입 없이 저장 → 기기 변경 시 복구 없음.
- 단일 프로세스 JSON 저장 → 영구 볼륨 필수, 다중 인스턴스는 DB 교체 필요.
- 별칭과 토글은 전달 이력을 보존. 버스/요일/목표시간/도보 설정 변경은 새 알림 설정으로 취급한다. 새 설정에 대해 같은 날 추가 안내를 받을 수 있다.
- 실제 API 인증과 HTTPS 모바일 수신은 운영 환경에서 검증해야 한다. 저장소 반영이 서비스의 인터넷 배포를 의미하지 않는다.
