# 미리타 구현 설계

목표: 첨부 brand.md와 design.md의 가입 없는 경로 설정 → 저장 결과 흐름을 실제 웹 서비스로 구현한다. 기존 HTML의 체험 흐름을 경로 관리, 버스 정보 조회, 웹 푸시로 확장한다.

## 범위와 선택
- Node.js 24 LTS, 외부 런타임 의존성 없는 HTTP 서버와 ES 모듈 PWA. 단일 인스턴스용 원자적 JSON 저장소, 영구 볼륨 필수.
- 서울 버스 API를 첫 제공처로 선택한다. 지역은 원문에 없으므로 구현 가정이다. 인증키가 없으면 명시적 체험 모드이며 실제 도착 정보나 자동 알림으로 표시하지 않는다.
- 첫 화면은 경로 설정, 별도 / 소개 페이지는 7블록 스토리. 로고·키비주얼과 primary #2463C5, bg #F3F8FF, text #163465, radius 8px 적용. 시스템 한글 서체로 외부 폰트 통신을 피한다.
- 익명 기기 쿠키로 경로 최대 10개를 서버 저장. 새 브라우저/쿠키 삭제 시 복구되지 않는다. 계정과 결제는 범위 밖이다.
- 정류장 이름 검색 → 경유 버스 선택을 한 화면에서 수행. 현재 위치는 사용자 요청 시에만 500m 이내 주변 정류장 검색에 사용하며 서버에 저장하지 않는다.
- 도보 시간은 사용자가 입력(1~60분). 길찾기 API 없이 실제 도보 시간을 자동 계산했다고 표시하지 않는다. 여유시간 1~10분, 기본 1분.
- 평일 기본값, 요일 선택 가능. 사용자가 설정한 탑승 목표 시각 전 60분 동안 60초 주기로 확인. 자정 전후 일정도 서울 시간 기준 처리.
- 버스 첫 도착까지 30분 이하일 때 안내, 도보+여유시간 이하일 때 출발 안내. 같은 경로 설정·탑승일·단계당 1회 (별칭·알림 토글 시 이력 유지, 버스·시간·요일·도보 설정 변경 시 새 설정으로 취급), 갱신 실패 또는 도착 정보 없음은 발송하지 않는다. 이미 늦은 버스는 다음 버스를 확인하도록 안내.
- VAPID 설정과 HTTPS, 사용자 권한이 있으면 Web Push 구독·테스트 발송·스케줄 발송. 체험 모드에서는 자동 발송하지 않는다. 푸시 전달은 브라우저·OS 정책에 영향받으며 배달을 보장하지 않는다.
- 경로별 알림 켜기/끄기, 수정, 확인 후 삭제, 전체 기기 데이터 삭제, 서비스 공유 지원.

## 서버와 데이터
server/domain.js는 입력 검증과 출발 판단, store.js는 직렬 트랜잭션과 디스크 저장, transit.js는 서울 API 정규화, push.js는 RFC8291/8292 전송, scheduler.js는 반복 실행, app.js는 API·기기 격리·정적 파일 제공을 맡는다.

브라우저는 동일 출처 /api만 사용한다. 서비스키와 VAPID 비밀키는 환경변수이며 브라우저에 전달하지 않는다. 쿠키 HttpOnly/SameSite=Strict, HTTPS에서 Secure, JSON 쓰기 요청 Origin 검사, 본문 제한, 요청 제한, 공개 푸시 공급자 허용목록, 사용자별 접근 통제를 적용한다. 비밀·정확 위치·푸시 주소를 로그로 출력하지 않는다.

## 검증과 운영 조건
입력 경계값·원자적 저장 실패·기기 격리·외부 API 실패·푸시 만료·중복 발송·시간대와 자정 경계·RFC 공식 암호화 벡터·HTTP 통합을 자동 테스트한다. Playwright로 모바일과 데스크톱 경로 생성/수정/삭제 및 새로고침 유지, 빈 결과를 확인한다.

실제 외부 버스 API와 모바일 푸시 현장 검증은 제공되지 않은 인증키와 HTTPS 운영 환경이 필요하다. 코드 및 모의 응답 통합 검증과 이를 구분하여 보고한다. 광고 운영은 광고 공급자 정보가 없어 광고 SDK 없이 가격 원칙만 유지한다.
